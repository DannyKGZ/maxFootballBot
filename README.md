# max-football-bot

Бот для мессенджера MAX: автоматическая запись на футбол по понедельникам и
пятницам в 9:00, основой на 10 мест (дальше резерв), обработкой `+Имя` / `-Имя` и
подтверждениями через инлайн-кнопки.

Реализовано напрямую поверх официального REST API MAX
(`https://platform-api2.max.ru`, см. https://dev.max.ru/docs-api), без
сторонних SDK — так проще проверить и поддерживать код, и не приходится
зависеть от версии обёртки. Основные эндпоинты, которые использует бот:

| Метод | Путь | Назначение |
|---|---|---|
| `POST` | `/subscriptions` | регистрация вебхука |
| `POST` | `/messages?chat_id=` | отправка нового сообщения |
| `PUT` | `/messages?message_id=` | редактирование сообщения (обновление списка) |
| `DELETE` | `/messages?message_id=` | удаление сообщения (очистка чата после голосования за MVP) |
| `POST` | `/answers?callback_id=` | обязательный ответ на нажатие кнопки |
| `POST` | `/messages?user_id=` | личное сообщение (инструкция нажавшему) |
| `GET` | `/chats/{chatId}/members/admins` | проверка прав администратора (для админ-команд) |
| `GET` | `/chats/{chatId}/members` | участники чата для `/Всем` |

## Запуск на сервере (Timeweb Cloud)

Пошаговая инструкция — в **[DEPLOY.md](DEPLOY.md)**: какой сервер заказать,
установка одной командой (`deploy/setup-server.sh`), перенос `.env` и базы с ПК,
управление, обновление и бэкапы. На сервере бот работает в режиме
`UPDATES_MODE=polling` — без домена, SSL и туннеля.

## TLS / вебхук

MAX принимает вебхуки **только по HTTPS на порту 443**. С 25 мая 2026
самоподписанные сертификаты и обычный HTTP больше не поддерживаются — нужен
сертификат от доверенного центра сертификации или сертификат Минцифры.

Два варианта:

1. **TLS прямо в Node** — укажите `TLS_CERT_PATH` и `TLS_KEY_PATH` в `.env`,
   бот поднимет `https.createServer` сам.
2. **TLS на reverse-proxy** (рекомендуется для прод) — nginx/Caddy/Traefik
   терминируют HTTPS и проксируют на бота по HTTP; тогда `TLS_CERT_PATH` /
   `TLS_KEY_PATH` в `.env` оставьте пустыми.

Если `AUTO_REGISTER_WEBHOOK=true`, при старте бот сам вызовет
`POST /subscriptions` с `PUBLIC_WEBHOOK_URL` и подпишется на
`message_created` и `message_callback`. Секрет из `WEBHOOK_SECRET`
проверяется в заголовке `X-Max-Bot-Api-Secret` входящих запросов. Заодно он удаляет подписки на все
другие адреса (старые туннели) — иначе MAX продолжает слать обновления в
пустоту, и доставка может ломаться.

### Туннель до локального бота (Cloudflare quick tunnel)

Сейчас `PUBLIC_WEBHOOK_URL` смотрит на **Cloudflare quick tunnel**
(`cloudflared tunnel --url http://localhost:8443`, домен вида
`*.trycloudflare.com`) — он бесплатный и не требует своего домена, но при
**каждом перезапуске `cloudflared` выдаёт новый случайный адрес**, и старый
`PUBLIC_WEBHOOK_URL` в `.env` перестаёт работать.

> **Постоянный (именованный) туннель Cloudflare** с фиксированным адресом
> требует домена, добавленного в ваш аккаунт Cloudflare (zone) — без домена
> Cloudflare его не выдаёт. Если такой домен появится, настройка: `cloudflared
> tunnel login` → `cloudflared tunnel create max-football-bot` → `cloudflared
> tunnel route dns max-football-bot <поддомен>.<ваш-домен>` → указать
> `PUBLIC_WEBHOOK_URL=https://<поддомен>.<ваш-домен>/webhook`.

Туннель запускается с `--protocol http2`: на этом ПК (WSL) протокол QUIC,
который `cloudflared` использует по умолчанию, постоянно рвётся (`timeout: no
recent network activity`), и сообщения из MAX не доходят до бота; встроенная
проверка `cloudflared` так и пишет: `QUIC connection failed`,
`suggested_protocol=http2`.

Пока домена нет, используйте [`scripts/dev-tunnel.sh`](scripts/dev-tunnel.sh)
— он сам поднимает `cloudflared`, вытаскивает новый URL из его вывода,
подставляет его в `PUBLIC_WEBHOOK_URL` и запускает бота (который затем сам
перерегистрирует вебхук на актуальный адрес):

```bash
./scripts/dev-tunnel.sh          # для разработки — под капотом npm run dev
./scripts/dev-tunnel.sh start    # для прод-режима — npm run build && npm start
```

Ctrl+C останавливает и бота, и туннель вместе (см. `trap` в скрипте).

#### Автозапуск и автовосстановление (systemd)

Чтобы бот и туннель поднимались сами после падения или перезагрузки WSL,
есть готовый юнит [`scripts/max-football-bot.service`](scripts/max-football-bot.service)
(user-уровня, sudo не нужен для самого запуска бота — только один раз для
`enable-linger`, чтобы сервис жил без открытого логина):

```bash
mkdir -p ~/.config/systemd/user
cp scripts/max-football-bot.service ~/.config/systemd/user/
systemctl --user daemon-reload
systemctl --user enable --now max-football-bot.service
loginctl enable-linger "$USER"   # чтобы сервис работал и без открытой сессии/после ребута WSL

# Проверить статус и логи:
systemctl --user status max-football-bot.service
journalctl --user -u max-football-bot.service -f
```

При таком запуске каждый рестарт сервиса поднимает **новый** URL туннеля —
это ожидаемо (см. выше про quick tunnel) и не требует ручных действий: бот
сам подставит новый адрес в `.env` и перерегистрирует вебхук.

## Несколько чатов

Бот может вести несколько чатов одновременно: `CHAT_IDS=-111,-222` в `.env`
(старое `CHAT_ID` с одним чатом тоже работает). У каждого чата **свои**:
запись и список, расписание публикации (`/расписание`), шапка и время игры
(`/описание`), игры (`/игры`), размер основы (`/лимит`), голосование и рейтинг MVP, напоминания и реквизиты оплаты (`/оплата`). Админы — свои
в каждом чате: это администраторы чата в MAX, права проверяются у того чата,
где выполняется команда.

- Чтобы узнать ID нового чата: добавьте туда бота (с правами админа) и
  напишите что-нибудь — в логе появится
  `сообщение из чата chat_id=… — его нет в CHAT_IDS`. Допишите этот ID в
  `CHAT_IDS` и перезапустите бота. В чатах не из списка бот молчит.
- **Личка с ботом**: команды и кнопки действуют на чат, в котором вы
  состоите. Кто состоит в нескольких чатах бота, видит в меню кнопку
  `🔁 Чат: Название` — ею выбирается, каким чатом управлять (выбор
  запоминается). Админ одного чата не видит панель другого.

## Команды

Команды разделены на две группы, и бот показывает их раздельно:
**участники видят только свои команды**, админские команды есть только в
инструкции администратора (она приходит админу в личку) и в панели
администратора. Меню команд MAX (подсказки при вводе `/`) общее для всех,
поэтому бот ставит в него только команды участников: `/status`, `/mvp`, `/help`.

| Команда | Кнопка под записью | Что делает |
|---|---|---|
| `+` | ➕ Записаться | записать себя |
| `+Имя` · `+Имя +Имя` | — | записать друга / сразу нескольких |
| `-` · `-Имя` | ➖ Убрать себя | убрать свою запись (при нескольких — выбор кнопками) |

| `/составы` | — | команды после дележки |
| `/mvp` (`/мвп`) | 🏆 Рейтинг MVP | рейтинг MVP за сезон и за всё время |

> администраторов чата MAX (проверяется у MAX при каждой команде). Если
> админскую команду напишет не админ, бот ответит «доступна только
> администраторам».

### Типичный цикл недели

1. **Пн и пт в 9:00** (или в дни, выбранные через `/расписание`) бот сам
   публикует запись «Футбол в Среда ДД.ММ.ГГГГ года / В 21:30».
   Предыдущая запись при этом закрывается и уходит в архив. Если нужно открыть
   запись раньше или вне расписания — админ пишет **`/старт`**.
2. **Участники записываются**: `+`, `+Рома`, `+Сергей +Владимир` (до 5 имён за
   раз). Первые 10 идут в основу, остальные — в «(Резерв)». Кто-то отказался —
   пишет `-`, резервист поднимается автоматически, и бот пишет об этом в чат.
3. **За 5 часов до игры** бот напоминает в чате, сколько людей в основе и резерве.
   **Оплата**: за 3, 2 и 1 час до игры и через 1 и 2 часа после бот присылает
   отдельное сообщение «💰 Оплата за игру» — 350 ₽ с игрока на 💳 Сбер
   0000000000, с **упоминанием** каждого, кто записывал игроков основы, и суммой
   за всех его игроков (например, «Ruslan — 700 ₽ (Ruslan, Тест1)»). Резерв не
   платит. Каждое новое напоминание заменяет предыдущее, чтобы не копились.
4. **После игры** админ пишет **`/голосование`** — бот присылает список игроков
   прошедшей игры кнопками (даже если по расписанию уже открыта новая запись).
   Голосуют только записанные, по одному голосу за каждую свою запись; кто не
   записан — только смотрит, кто за кого проголосовал.
5. Когда проголосовали все, админ пишет **`/итоги`** (или голосование само
   закроется через 24 часа): бот объявляет MVP, засчитывает его в общий рейтинг
   и удаляет из чата свои служебные сообщения (остаются записи и итог MVP).
6. В любой момент любой участник может написать **`/mvp`** и посмотреть рейтинг.

### Для всех участников

#### `+` — записать себя
Пишете один плюс. Бот берёт данные вашего профиля MAX и добавляет строку:
`1. Ruslan` — `first_name` и `last_name` (если есть), без скобок. Если вы уже в списке, повторный `+` ничего не делает (бот ни о чём
не спрашивает); друга записывают сразу с именем — `+Рома`.

#### `+Имя` и `+Имя +Имя +Имя` — записать других (или нескольких сразу)
Примеры: `+Рома`, `+Сергей +Владимир +Андрей`, `+Иван Петров`.
- Имена добавляются **сразу**, даже если вы уже записаны или не записаны сами
  — подтверждений нет; список обновляется одним сообщением.
- Все записанные вами получают **ваш** `user_id`: у вас столько голосов в
  голосовании, сколько записей (себя + друзья).
- Пишите имя каждый раз одинаково («Рома», а не «Ромка») — рейтинг MVP
  склеивает игроков по имени без учёта регистра.

#### `-` и `-Имя` — убрать запись
Если не можете прийти, напишите `-`.
- **Записана одна ваша запись** — бот спросит «Удалить из списка: Ruslan?» (Да/Нет).
- **Вы записали нескольких** (себя и Руслана, друзей) — бот покажет кнопки с
  именами: «Кого удалить из списка?» `[Рома] [Руслан] [Отмена]`. Нажали на имя —
  запись сразу пропадает, повторных вопросов нет.
- **`-Рома`** сразу указывает, кого убрать (одна такая запись — переспросит
  Да/Нет; несколько с одним именем — покажет выбор).

Удалить можно **только записи со своим аккаунтом**; чужого игрока так не
убрать. Резервист после удаления поднимается в основу, а сообщение с
вопросом/кнопками исчезает из чата.

#### `/статус` (`/status`) — актуальна ли запись
Любой участник может проверить, что происходит с записью:
- **✅ Запись актуальна** — на какую игру (день, дата, время) и сколько до неё
  осталось; когда запись открыта; основа «N из 10» и свободные места; резерв.
- **⚠️ Запись устарела** — игра уже прошла, а новая запись ещё не открыта.
- **⛔ Сейчас записи нет** — запись закрыта (и когда была последняя игра).
- Идёт ли голосование за MVP и когда бот сам откроет следующую запись
  (расписание из `/расписание` или из `.env`).

Новый `/статус` заменяет предыдущее сообщение со статусом, так что в чате
всегда одно. В личке с ботом `/статус` показывает статус общего чата.

#### `/mvp` (или `/мвп`) — рейтинг MVP
Показывает, сколько раз каждый игрок выигрывал голосование, двумя списками:
**сезон** (с даты последнего сезонного сброса) и **за всё время**; 🥇🥈🥉 и
далее по убыванию. Пока голосований не было, рейтинг пуст.
В чате всегда одно сообщение с рейтингом: новый `/mvp` (или кнопка) заменяет
предыдущее, а если несколько человек нажали одновременно — бот отвечает один раз.

#### `/имя` и «✏️ Изменить имя» — своё имя в списке
Если в группе несколько «Русланов», каждый может задать, как его показывать:
кнопка **«✏️ Изменить имя»** в личке с ботом (бот попросит написать имя) или
команда `/имя Руслан Большой` (в чате или в личке). Имя запоминается: в
текущей записи строка сразу переименовывается, а при следующих записях через
«+» бот подставляет его сам — в списке будет `1. Руслан Большой`. Менять можно сколько угодно раз; `/имя` без
текста показывает текущее.

#### Кнопки
Под сообщением записи — кнопки для всех участников:

| Кнопка | Эквивалент |
|---|---|
| ➕ Записаться | `+` |
| ➖ Убрать себя | `-` |
| 🏆 Рейтинг MVP | `/mvp` |
| ℹ️ Инструкция | — (приходит лично вам, см. ниже) |

**ℹ️ Инструкция** (или команда `/help`) — в групповом чате сообщение увидели
бы все, поэтому бот присылает инструкцию **в личный чат** тому, кто нажал:
- **участнику** — только команды участника (запись, удаление, голосование,
  `/статус`, `/mvp`, `/help`), напоминания об оплате и **его личный статус**:
  кого он записал (и кто в резерве), сколько голосов отдал из скольких.
  Админских команд в ней нет;
- **админу** — инструкцию администратора: состояние чата (запись, голосование,
  расписание), **все админские команды** по разделам (запись, голосование и
  рейтинг MVP, объявления) с кнопками панели, а в конце — команды участников.

Инструкция администратора длиннее лимита MAX (4000 символов на сообщение),
поэтому приходит **несколькими сообщениями**: текст делится по целым разделам,
так что раздел не разрывается посередине, а в конце каждой части — «— часть N
из M». Разбивкой занимается `messageParts.ts`.

Если человек ещё ни разу не открывал бота в личке, MAX не даёт боту написать
первым — тогда нажавший получит подсказку (всплывающую для кнопки, сообщением
в чате для `/help`): открыть бота, нажать «Начать» и повторить. Не-админ,
написавший боту в личку что угодно, сразу получает свою инструкцию.

Записать **друзей** кнопкой нельзя (нужно вводить имя) — для этого `+Имя`
текстом. Под сообщением голосования — кнопки кандидатов со счётчиком
(`Валера · 3`).

Вопросы «Да/Нет» и «Кого удалить?» работают только для того, кому адресованы,
и одноразовые: после нажатия сообщение с кнопками удаляется из чата.

### Только для администраторов

#### Личный чат с ботом — кнопки для всех
Любой участник может открыть бота в MAX (кнопка «Начать» или любое
сообщение). Бот ответит приветствием с личным статусом и кнопками, которые
работают прямо из лички и действуют на запись общего чата:

| Кнопка | Что делает |
|---|---|
| ➕ Записаться | записать себя (если уже записаны — только уведомление) |
| ➖ Убрать себя | выбрать, какую из своих записей убрать (себя или записанного друга) |
| 📋 Статус | статус записи — ответом в личку |
| 🏆 Рейтинг MVP | рейтинг за сезон и за всё время — ответом в личку |
| ℹ️ Инструкция | инструкция участника |

Ответы на эти кнопки приходят только в личку и в общий чат не попадают. У
админа эти же кнопки стоят над его панелью.

#### Панель администратора (личный чат с ботом)
В групповом чате MAX кнопки под сообщением видят **все** участники — показать
их только админу нельзя. Поэтому админские кнопки вынесены в личный чат:

1. Откройте бота в MAX и нажмите «Начать» (или напишите ему что угодно).
2. Бот проверит, что вы админ выбранного чата (из `CHAT_IDS`), и пришлёт
   панель с текущим состоянием и кнопками:
   `🔄 Новая запись` · `⏹ Закрыть запись` · `🗳 Начать голосование` ·
   `🏁 Итоги голосования` · `🗓 Расписание`.
3. Нажатие выполняет действие **в общем чате**; результат приходит
   всплывающим уведомлением. Подтверждения («Точно начать новую?») и диалог
   расписания тоже идут в личке — участники их не видят.

Не-админу бот в личке вместо панели присылает его инструкцию и статус.
Текстовые команды ниже по-прежнему работают прямо в общем чате.


#### `/старт` (`/start_signup`) — открыть запись вручную
Публикует новое сообщение записи прямо сейчас — не ожидая
расписания. Если предыдущая запись ещё идёт и в ней есть игроки, бот спросит
подтверждение («Точно начать новую? Старая запись закроется»); при «Да» старая
помечается закрытой и открепляется. Пустая запись заменяется без вопросов.

#### День игры и закрытие записи
- **День игры — на следующий день после публикации по расписанию**, в 20:30
  (время начала из `/описание` или `GAME_TIME`). Расписание «Вт, Чт, Вс в
  11:59:55» → игры в Ср, Пт и Пн. `/старт` вне расписания открывает запись на
  ближайший из этих дней. Если расписание не еженедельное (сложный cron) —
  игра в `GAME_DAY_OF_WEEK`.
- **Запись идёт до начала игры.** В момент начала бот закрывает её: под
  сообщением записи пропадают кнопки, появляется «🔒 Запись закрыта — игра
  началась», а на «+»/«-» бот отвечает, что запись закрыта. Список
  фиксируется — по нему идут оплата после игры и голосование за MVP. Админ
  может поправить состав и после начала (`/удалить`, `/переименовать`).

#### `/удалить`, `/переименовать` — правка списка админом
- `/удалить 3` или `/удалить Имя` — убрать любого игрока (номер — как в
  списке). Резервист поднимается, бот сообщает об этом.
- `/переименовать 3 Новое имя` (или `/заменить Петя Пётр`) — исправить имя.
- `/поменять 1 на 12` (или `/поменять 1 12`) — поменять двух игроков местами по
  номерам в списке. Так админ переводит человека из резерва в основу, а
  другого — в резерв: кто встал на место в пределах основы, тот в основе.
  Бот публикует свежий список и пишет, кто куда переместился.
- В личке с ботом: кнопка **«✏️ Список игроков»** в панели — игроки кнопками,
  выбрал → «❌ Удалить» или «✏️ Переименовать» (новое имя — сообщением).

#### `/дележка` — деление на команды
1. Админ пишет `/дележка` (или кнопка «⚽ Дележка» в панели) — бот публикует
   основу кнопками, админ отмечает **двух капитанов**. Сразу по номерам:
   `/дележка 2 5`.
2. Капитаны **по очереди, по одному** (⚪ ⚫ ⚪ ⚫ …) выбирают игроков кнопками под
   сообщением. Нажать может сам капитан (тот, кто записывался под этим именем)
   или админ — если капитана записали «за друга» и своего аккаунта у него нет.
   Не в свою очередь бот не даст выбрать.
3. Когда игроки основы закончились — «⚽ Составы готовы!» с обеими командами,
   а ниже в том же сообщении — напоминание об оплате (сумма и реквизиты чата) с
   упоминанием игроков: каждому, кто записывал, — его сумма (`@Ruslan — 700 ₽
   (Ruslan, Петя)`). Резерв в дележке не участвует.
4. **Держится внизу чата.** С начала дележки и до итогов голосования за MVP её
   сообщение (а во время голосования — голосование) всегда последнее: как
   только в чате появляется новое сообщение, бот через 2 с (`STICKY_DELAY_MS`)
   публикует его заново, а старое удаляет. После итогов голосования — не держит. `/составы` — показать команды любому, они же
   видны в `/статус`. `/дележка сброс` — отменить.

#### `/легенда` и `/манишкаНосец` — кто записан всегда

У каждого чата две роли; их носителя бот сам записывает в **каждую новую
запись**, и он всегда стоит наверху списка:

```
1. Витя — Легенда 🏆🏅⚽
2. Руслан — 👕 манишкаНосец
3. …
```

- **Легенда** — один на чат, всегда 1-й, действует **ровно год** с назначения
  (потом бот перестаёт его записывать и помечать).
- **манишкаНосец** — у кого манишки, всегда 2-й (после легенды), один на чат.
- Назначает админ: `/легенда` или `/манишкаНосец` (в чате или боту в личку,
  либо кнопки «🏆 Легенда» / «👕 МанишкаНосец» в панели), админ выбирает
  кнопкой. Легенда — из **всех участников чата** (без ботов и удалённых
  аккаунтов, по алфавиту, по 30 на страницу с листанием); манишкаНосец — только
  из **записавшихся** на игру (текущая запись, если её нет — прошлая). Если запись открыта,
  новый носитель сразу ставится на своё место, а прежний манишкаНосец,
  записанный только из-за роли, убирается. `… сброс` — снять роль.
- Если у игрока нет своего аккаунта и его записывает друг (`+Витя` от
  Pasechnik) — его тоже можно выбрать: бот будет записывать его от имени того
  же друга, и убрать его может этот друг или админ. Нет в списках — укажите
  имя: `/манишкаНосец Володя` (тогда его записывает админ, давший команду).
- **После игры** рядом с голосованием за MVP бот присылает кнопку
  «👕 Я забрал манишки». Нажать может только тот, кто играл (основа), и только
  один: кнопка меняется на «↩️ Я ошибся» — её нажимает забравший (или админ),
  и манишки снова может забрать другой игрок.
- Не может прийти — носитель роли удаляется из записи как обычно (сам «-» или
  админ `/удалить`); роль при этом сохраняется.
- Текущие роли видны в `/статус`. Легенда может и сам забрать манишки — тогда
  в списке он один раз, первым.

#### `/игры` — свой день публикации и своё время у каждой игры

Обычное расписание (`/расписание`) открывает запись на игру **на следующий
день**, время у всех игр одно. Если нужно иначе — например, в понедельник в
12:00 открыть запись на среду 21:20, а в четверг в 12:00 — на воскресенье
20:20, — админ пишет в чат (или боту в личку):

```
/игры Пн 12:00 Ср 21:20, Чт 12:00 Вс 20:20
```

Пары «день и время публикации → день и время игры» через запятую; дни можно
писать полностью («среда»), между временем и днём игры можно ставить «→» или
«-». У каждого чата свои игры. `/игры` — показать, `/игры сброс` — вернуться
к обычному расписанию; настройка через `/расписание` тоже заменяет `/игры`.
Текущую запись команда не меняет — новые даты действуют со следующей публикации.

#### `/описание` (`/description`) — шапка записи
По умолчанию запись начинается с «Футбол в Среда 30.09.2026 года / В 21:30».
Админ пишет, как шапка должна выглядеть, — прямо с примером дня и даты:

```
/описание Футбол в Среда 30.09.2026 года
В 20:30 - 21:30
```

- **День недели и дата** из текста становятся подстановками — для каждой
  записи бот ставит её настоящие день и дату (следующая: «Среда 07.10.2026»).
  Остальной текст остаётся как написан («В 20:30 - 21:30»).
- **Первое время `ЧЧ:ММ`** в тексте — начало игры: на него переносится текущая
  запись и все следующие, от него считаются напоминание, оплата и `/статус`
  (заменяет `GAME_TIME` из `.env`).
- Шаблон общий: действует на текущую запись (сообщение перерисовывается сразу)
  и на все следующие.
- `/описание` без текста — показать текущую шапку; `/описание сброс` — вернуть
  стандартную. Только для админа; работает и в личке с ботом.
- Для своих шаблонов можно писать подстановки явно: `{День}`/`{день}`,
  `{дата}` (ДД.ММ.ГГГГ), `{дата_кратко}` (ДД.ММ), `{время}`.

#### `/закрыть` (`/close_signup`) — закрыть запись
Закрывает текущую запись **без** открытия новой (сообщение помечается «Запись
закрыта» и открепляется). Если в ней есть игроки — спросит подтверждение.
После этого запись появится снова только по расписанию или по `/старт`.

#### `/расписание` (`/schedule`, `/голосование_расписание`) — расписание авто-публикации
Диалог из кнопок:
1. Выберите **дни недели** `[Пн] [Вт] … [Вс]` — нажатие включает/выключает день
   (выбранные с ✅) → **«Готово»**.
2. Выберите **время**: `09:00 … 21:00` кнопками или **«Другое время»** и
   напишите `ЧЧ:ММ:СС` (например `20:30:15`; секунды можно не писать — `20:30`
   значит `20:30:00`). Время — в часовом поясе `TIMEZONE`.
3. Бот сохраняет расписание в `SCHEDULE_FILE` и сразу применяет его, без
   перезапуска. Сохранённое расписание важнее `CRON_SCHEDULE` из `.env`.

В начале диалога бот показывает, какое расписание действует сейчас и откуда
оно (из `/расписание` или из `.env`). Кнопка **«♻️ Сбросить расписание»**
удаляет расписание, заданное через `/расписание`, и сразу — без перезапуска —
возвращает значение по умолчанию `CRON_SCHEDULE` из `.env`.

Диалог можно прервать кнопкой **«Отмена»**; работает только у админа, который
его начал.

#### `/голосование` (`/vote_mvp`) — начать голосование за MVP
Берёт **последнюю сыгранную игру** (у которой дата уже прошла): текущую запись
или предыдущую, закрытую по расписанию, `/старт` или `/закрыть`. Поэтому
голосование можно запустить и после того, как открылась запись на следующую
игру. Если сыгранной игры нет (например, хотите проверить заранее) — берётся
текущая запись. Бот присылает список игроков кнопками (основа + резерв).
- Голосовать может только тот, чей аккаунт есть в записи; голосов у него —
  столько, сколько записей на его аккаунте. Остальные получают уведомление
  «Голосовать может только тот, кто был записан».
- Голосование открытое: в сообщении обновляется лог «кто → за кого».
- Одновременно может идти только одно голосование.
- **Только основа.** Кандидаты — игроки основы (10); резерв не играл, поэтому
  он не кандидат и голосов не даёт. Голосов у человека столько, сколько у него
  записей в основе (себя и друзей). Всего голосов — по числу игроков основы.
- **Голосование запускается само** через `VOTE_AUTO_START_MINUTES` минут после
  начала игры (по умолчанию 60 — при игре в 20:30 это 21:30, конец игры), если
  админ не запустил его раньше. Только один раз на игру и не позже 6 часов
  после этого срока (по давно прошедшей игре само не открывается).
- **Как только все игроки основы отдали все голоса — голосование закрывается
  само** и бот сразу показывает итоги (как `/итоги`).
- **Счёт прямо на кнопках кандидатов** — прогресс-бар на шкале всех голосов:
  `Димас ▰▰▰▰▱▱▱▱▱▱ 4`. Прогресс показан **только у тех, за кого голосовали**,
  у остальных на кнопке просто имя; в итогах — тоже только набравшие голоса.
- **В сообщении — список голосующих**: 🔴 — ещё не голосовал (у кого
  несколько голосов — «голосов: 2»), ✅ — проголосовал, и сразу видно, за кого:
  `✅ Pasechnik → Ашот, Витя`. Сверху — «Отдано голосов: 6 из 10».
- **За себя голосовать нельзя** (своя запись через «+» или под своим именем);
  за друзей, которых вы записали, — можно.
- После каждого голоса бот присылает **свежее сообщение голосования внизу
  чата**, а старое удаляет. `/голос` (для всех) — вытащить голосование вниз
  чата в любой момент; если голосования нет, админу эта команда его запускает.

#### `/итоги` (`/finish_vote`) — закончить голосование
Публикует итог: победитель, результаты и полный лог голосов. **Победитель
получает +1 в рейтинг MVP.** В одном матче может быть **до 3 MVP**: при ничьей на
первом месте MVP — все лидеры, но не больше трёх (если лидеров больше — те трое,
кто набрал это число голосов раньше). Когда проголосовали все игроки основы,
голосование закрывается и победитель объявляется сразу, без `/итоги`. Затем бот
удаляет свои служебные сообщения, накопившиеся с прошлой очистки, кроме записи,
составов и итога MVP. MAX не даёт удалять сообщения старше 24 часов — такие пропускаются.

Если админ не подвёл итоги, голосование **закроется само** через
`VOTE_AUTO_CLOSE_HOURS` часов (по умолчанию 24) — с тем же итогом и очисткой и
пометкой «закрыто автоматически». MVP засчитывается один раз, даже если админ
нажмёт «Итоги» в ту же секунду.

#### `/Всем текст`, `@all текст` — объявление с упоминанием всех
Варианты записи: `/Всем …`, `/all …` или как в Telegram — `@all …`, `@всем …`,
`@все …`. Просто `@all` без текста отправит «Внимание всем!».

1. В общем чате бот публикует `📢 текст` и упоминает **всех участников**
   (кроме ботов и удалённых аккаунтов «DELETED USER») — каждому приходит
   уведомление. Список берётся у MAX (`GET /chats/{chatId}/members`,
   постранично). MAX отмечает в одном сообщении ограниченное число людей,
   поэтому упоминания идут **по 40 в сообщении** (и не длиннее 4000 символов):
   в чате на 80 человек — два сообщения.
2. **Копия в личку — выключена по умолчанию** (`ANNOUNCE_DM=false`). MAX не
   даёт боту написать первым тому, кто ни разу не открывал бота, поэтому на
   практике копия дошла 1 из 47. Если включить (`ANNOUNCE_DM=true`), копия
   придёт тем, кто открывал бота, а автору — итог «доставлено N из M».

Только для админа; из личного чата с ботом команда публикует объявление в
общий чат (тот, где написана команда). Отдельного встроенного «@all» в MAX нет — как и в
Telegram, его делает бот, упоминая каждого.

#### `/мвпСезонныйСброс` и `/мвпОбщийСброс` — сброс рейтинга MVP
Рейтинг ведётся в двух счетах: **сезонный** и **за всё время**. Каждая победа в
голосовании прибавляется к обоим, `/mvp` показывает оба списка (у сезона —
дата начала).

| Команда | Синонимы | Что обнуляет |
|---|---|---|
| `/мвпСезонныйСброс` | `/мвп_сезонный_сброс`, `/mvp_reset_season` | только сезонный счёт — начинается новый сезон, общий сохраняется |
| `/мвпОбщийСброс` | `/мвп_общий_сброс`, `/mvp_reset_all` | весь рейтинг — и общий, и сезонный |

Только для админа и **с подтверждением**: бот спрашивает «Да/Нет» (кнопки
работают только у того, кто запросил), сброс необратим. После сброса бот
объявляет об этом в общем чате. Объединения имён (`/объединить`) при сбросе
сохраняются. То же — кнопками «🧹 Сброс сезона MVP» / «🗑 Сброс всего MVP» в
панели админа (подтверждение приходит в личку). Команды работают и в личке с
ботом — тогда сбрасывается рейтинг выбранного чата.

При обновлении существующей базы все прежние победы засчитываются и в
текущий сезон.

#### `/объединить Рус = Ruslan` (`/merge`) — склеить игрока в рейтинге MVP
Рейтинг считает игроков по имени, поэтому «Рус» и «Ruslan» — два разных игрока.
Команда переносит все MVP имени слева к имени справа, а будущие победы «Рус»
тоже будут засчитываться «Ruslan». Работает в общем чате и в личке с ботом; в
панели админа есть кнопка «🔗 Объединить в рейтинге» с подсказкой и текущим
рейтингом.

На чат может быть только одно активное голосование одновременно. Список
кандидатов и лимиты голосов фиксируются в момент `/голосование` и не меняются,
даже если состав записи изменится позже.

## Логика (кратко)

- **Резерв**: `isReserve` пересчитывается по позиции в списке — первые
  `MAX_PLAYERS` (по умолчанию 10) считаются основой, остальные — резервом.
  Это применяется и при добавлении, и при удалении игрока (если из основы
  кто-то ушёл, следующий по очереди резервист автоматически поднимается).
- **`+` / `+Имя` / `+Имя +Имя`**: явные имена добавляются сразу, независимо
  от того, записан ли сам автор; все они получают его `userId` (в MAX нет
  отдельного ID у человека, которого записывают через чужой аккаунт) и идут
  отдельными строками. Голый `+` записывает автора по профилю; если он уже
  записан сам — ничего не происходит (без вопросов).
- **`-` / `-Имя`**: удаляет запись **только с `userId` отправителя** (по ТЗ,
  п.4.3 — чужие записи не трогаются). Одна своя запись — вопрос Да/Нет; несколько
  (себя + друзей) — кнопки выбора, выбор удаляет сразу.
- **Кнопки чужие/свои**: payload кнопки содержит `userId`, для которого она
  предназначена. Нажатие другим человеком в чате даёт **только личное**
  уведомление "Вы не участвуете в этой записи" через `POST /answers`, без
  изменений в чате.
- **Диалоги Да/Нет одноразовые**: после нажатия любой кнопки в подтверждающем
  диалоге ("Вы уже записаны...", "Удалить бронирование?", рестарт/закрытие
  записи) само сообщение с кнопками удаляется из чата (`DELETE /messages`) —
  чтобы по нему нельзя было случайно нажать повторно.
- **Обязательный ответ на callback**: `POST /answers` вызывается в любом
  случае — иначе MAX считает нажатие необработанным.
- **Рейт-лимиты**: `rateLimiter.ts` держит очередь на чат (≤2 RPS) поверх
  общей очереди (≤30 RPS), через неё идут все вызовы `sendMessageToChat`,
  `editMessage`, `answerCallback`.
- **Хранение — SQLite** (`DB_FILE`, по умолчанию `./data/bot.db`, библиотека
  `better-sqlite3`). В базе всё состояние: текущая и прошлая (архивная)
  запись, активное голосование с голосами, открытые вопросы «Да/Нет», список
  сообщений для очистки, рейтинг MVP с объединёнными именами и расписание.
  Каждая правка сразу пишется в базу (режим WAL — устойчив к сбоям), так что
  перезапуск ничего не теряет. В памяти — только кэш тех же данных, чтобы
  одновременные сообщения не затирали изменения друг друга, и незаконченный
  диалог `/расписание`. Запись и голосование лежат JSON-документом по
  `chat_id` (внутри вложенные списки игроков и голосов), рейтинг и расписание —
  обычными колонками. Игрок в рейтинге — это **имя** (без учёта регистра): у
  людей, записанных «за друга», нет своего ID в MAX.
- **Перенос со старых JSON.** При первом запуске бот сам переносит
  `data/sessions.json`, `data/schedule.json` и `data/mvp.json` в базу (любой из
  старых форматов) и переименовывает их в `*.json.migrated`. Перенос делается
  один раз — в базе ставится отметка. Посмотреть данные:
  `sqlite3 data/bot.db ".tables"`.
- **Бэкап** — достаточно скопировать `data/bot.db` (при остановленном боте;
  на работающем — `sqlite3 data/bot.db ".backup backup.db"`).
- **Если сообщение со списком удалили из чата**, бот при следующем изменении
  списка опубликует его заново, а не сломается.
- **Открытые вопросы живут `PENDING_TTL_MINUTES`** (15 мин): если человек не
  ответил на «Напишите имя игрока», его следующее сообщение через час не станет
  записью. Команды и `+`/`-` никогда не принимаются за ответ-имя.
- **Без закрепления**: бот не закрепляет сообщение записи.
- **Голосование за MVP**: у каждого, кто записан на игру, есть один голос за
  каждую свою запись в составе (включая записи "за друга"). Кто не записан —
  голосовать не может, но видит в открытом виде, кто за кого проголосовал.
  При подведении итогов (`/итоги`) бот удаляет все свои сообщения, отправленные
  с прошлой такой очистки, кроме записей (текущей и той, за которую голосовали)
  и итогового сообщения MVP —
  для этого `sendMessageToChat` в `maxApi.ts` попутно логирует id каждого
  отправленного сообщения в `store.ts`.

## Тесты

```bash
npm test
```

Собирает проект и прогоняет сквозные сценарии: бот запускается отдельным
процессом против подставного MAX API (в том же процессе, что и тесты), с

разных пользователей и нажимают те кнопки, которые бот сам прислал. Реальный

`node tests/run.js 03` (после `npm run build`).

## Что стоит проверить перед продакшеном

Документация `dev.max.ru/docs-api` местами описана скупо (некоторые страницы,
например про объект `Recipient` или точную схему `message_callback`
апдейта, недоступны напрямую), поэтому часть деталей выведена из связанных
источников (Go/PHP клиенты, обсуждения на GitHub). Перед боевым запуском
сверьте:

1. Точное имя поля с текстом всплывающего уведомления в `POST /answers`
   (в коде используется `notification`, как в вашем ТЗ).
2. Название поля с ID чата внутри `message.recipient` (в коде — `chat_id`,
   по аналогии с остальным API).
3. Реальный лимит длины `payload` у callback-кнопки — если MAX его
   ограничивает, укороченные ключи `{"a":.., "u":..}` в `keyboard.ts` уже
   рассчитаны на компактность, но стоит проверить на реальном боте.
4. Формат даты игры: бот считает "следующую дату по дню недели
   `GAME_DAY_OF_WEEK` и времени `GAME_TIME`" при каждой публикации — в ТЗ
   явно не описано, как именно выбирается дата матча, поэтому это
   осознанное допущение (настраивается через `.env`).
5. Право бота удалять сообщения (`DELETE /messages`) — по документации
   работает, если бот администратор чата; стоит проверить на реальном чате
   перед тем, как полагаться на автоочистку после `/итоги`.
7. Упоминания `max://user/ID` в `format: "html"` (`/Всем`, напоминание об
   оплате) — формат взят из описаний MAX API; проверьте, что людям реально
   приходит уведомление.
6. Лимит "24 часа" на удаление сообщений (`DELETE /messages`) — если
   голосование или запись висят в чате дольше суток, часть сообщений при
   очистке не удалится; бот это логирует и не падает, но список кандидатов
   на удаление стоит сверить на практике.
